npm 12 skips install scripts, and still exits 0

Find the dependencies that break when npm 12 skips their install scripts.

npm 12 no longer runs preinstall, install or postinstall for dependencies unless you approve them. The install succeeds, and later Puppeteer can't find Chrome, Prisma can't find its client, or sqlite3 has no bindings. Why upgrading npm quietly breaks projects

Failures show up later

A blocked script is only a warning. npm ci passes, then tests fail with "Could not find Chrome" or "Could not locate the bindings file", far from the cause.

Not every script matters

npm install-scripts ls lists every package with a script, but not which ones need it. esbuild and bcrypt 6 work without theirs; bcrypt 5 and sqlite3 don't. Approving everything defeats the security point.

CI changed too

Git dependencies are refused, abbreviated flags like --leg throw, --allow-scripts fails on project installs, npm shrinkwrap is gone and npm view --json returns an array.

      FAQ
      
  
      Does this upload my lockfile?
      No. Files are read and analysed in your browser. With registry lookup on, your browser asks registry.npmjs.org for the manifest of each package that has an install script (names and versions only). Repo scans read public files from GitHub. See the privacy note.
      
  
      How is this different from npm install-scripts ls?
      That command needs npm 12 and an installed tree, and lists every package with a script. This check works before you upgrade, needs no install, and tells you which scripts the package actually needs, with the exact command it runs. It also checks CI files, .npmrc and git dependencies.
      
  
      How are verdicts decided?
      First from a short list of packages with documented behaviour (for example Puppeteer, Cypress, Prisma, sqlite3, lefthook, bcrypt by version, esbuild). Otherwise from the script itself: prebuild-install, node-pre-gyp and node-gyp rebuild mean a native binary is downloaded or built; node-gyp-build means prebuilds ship in the package; message-only scripts are safe to deny. Anything else is marked "review".
      
  
      Does it support pnpm, Yarn or Bun?
      No, only npm's package-lock.json (v2 or v3). pnpm and Bun already block dependency scripts by default and have their own allowlists.
      
  
      Is this affiliated with npm or GitHub?
      No. It is an independent, open-source tool built from npm's public documentation.
