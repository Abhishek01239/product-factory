# Run 2026-10-12

Decision: BUILD — npm 12 Readiness Check (apps/npm12-check, v1.0.0)

## Problem
npm 12 (12.0.0 Jul 8; 12.2.0 = registry `latest` since Sep 30, 2026) skips dependency install scripts unless approved in `allowScripts`, and `npm ci` still exits 0, so Puppeteer / Prisma / sqlite3 / bcrypt 5 fail later. It also refuses git and tarball deps, throws on unknown/abbreviated flags, rejects `--allow-scripts` on project installs, removed shrinkwrap/adduser/star and changed `npm view --json`. Node.js still bundles npm 11 or older, so it arrives via `npm i -g npm@latest`, images, Corepack.

## Evidence
- npm 12 changelog + install-scripts/config docs (primary).
- Hands-on package tests (nilaykabariya.blog, Oct 11).
- Issues Oct 10-12: withastro/astro#17745, pingdotgg/t3code#9398, earendil-works/pi#6600, npm/cli#9912, #9835.
- Real repos: microsoft/vscode and cypress-io/cypress-example-kitchensink already commit allowScripts; jitsi/jitsi-meet would hit EALLOWGIT (6) and EALLOWREMOTE (4, one transitive so `root` is not enough).

## Built
Browser-only checker: lockfile `hasInstallScript` audit + real script text from registry.npmjs.org + verdict (documented list, version-aware; script heuristics), allowScripts coverage incl. stale pins, git/remote deps with root-vs-all, CI/Docker/package.json scan (unknown + abbreviated flags from npm's real 184 config definitions, EALLOWSCRIPTS, removed commands, Node engine, global installs), editable decisions -> allowScripts JSON + `npm install-scripts` commands + .npmrc lines, public repo scan, Markdown checklist.

## Testing

Real-repo runs found and fixed: root lockfile skipped by the 60-file cap (vscode), `https://github.com/x/y.git#sha` treated as tarball, workspace names shown as paths (and would have been sent to the registry), `node-gyp-build-optional-packages` not recognised, denied optional native deps (cpu-features) over-flagged. Added unknown-flag detection after confirming in the changelog (caught `--unsafe-perm` in vscode).

## Learnings
- Registry data beat the knowledge base: current Electron has no install script and bcrypt 5 vs 6 differ, so verdicts must come from the version's real script, with the static list only for documented behaviour.
- Pull authoritative lists from source (npm's config definitions) instead of hand-written ones; my first flag list would have missed unknown-flag errors.
- Two of eight real repos already maintain allowScripts: the problem is real, and the gap is "which ones are needed", not "how to allow".
- Distribution is still the bottleneck: 5 products live, 0 posts published.
