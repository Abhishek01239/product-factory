# Run 2026-10-14

Decision: BUILD: Supabase Grants Check (apps/supabase-grants-check, v1.0.0)

## Problem
On Oct 30, 2026 Supabase applies its explicit Data API grants default to every existing project (new projects since May 30). New `public` tables are no longer granted to anon/authenticated/service_role, so the next `create table` fails every supabase-js/REST/GraphQL call with 42501, even with service_role (grants are checked before RLS). Existing tables keep their grants, so nothing fails on the day; it fails on the next migration, preview branch or new project. The widely copied fix (`grant all on all tables in schema public to anon`) re-exposes tables without RLS.

## Built
Browser-only checker. Replays migrations (tables, views, serial sequences, RLS, policies, grants/revokes incl. ON ALL TABLES, ALTER DEFAULT PRIVILEGES, renames/drops, SECURITY DEFINER functions, config.toml exposed schemas). Reads supabase-js calls (`.from().select/insert/update/upsert/delete`, embedded resources in select strings, `.schema()`, `.rpc()`, server vs client context). Optional read-only catalog snapshot query for Dashboard-made tables and live auto-grant state. Findings: new tables without grants, RLS-off tables open to anon, auto-grant reliance, missing sequence USAGE, blanket grants, definer views, anon-executable definer functions, `using (true)` write policies for anon, calls no policy allows, tables missing from migrations. Output: per-table least-privilege GRANT migration (RLS-off tables only get commented lines; optional revokes), Markdown checklist, new-table template, `?repo=` deep link. PWA, OG image, CSP limited to api.github.com/raw.githubusercontent.com.

## Testing
- 18 unit tests pass; all other app suites unchanged.
- Postgres 18 verification of privilege rules: identity columns need no sequence grant, serial does; filtered UPDATE/DELETE and upsert need SELECT.
- End to end on PG18 with simulated Supabase roles: sample migrations alone, 42501 everywhere; after generated migration, all app operations work and anon is blocked from private tables.
- Snapshot SQL executed on PG18 and parsed back. Generated migration applied cleanly after vercel/nextjs-subscription-payments' real migrations.
- Real repos: nextjs-subscription-payments, chatbot-ui, next-supabase-stripe-starter, 3 Lovable apps. Fixed during testing: embedded resources (`prices(*)`) not counted as reads; added the open write policy rule after finding "Allow all for demo" policies in a Lovable app.

## Learnings
- A local Postgres (apt install postgresql) makes SQL-generating products verifiable end to end. Use it for any future DB product instead of trusting docs.
- Real AI-builder repos are the best false-positive source: they surfaced embedded-resource reads and wide-open demo policies in minutes.
- Privilege facts people miss (update/delete/upsert need SELECT) are the most useful content angle, more than the tool itself.
- 7 checkers live, 0 posts published: distribution is still the constraint, not building.
