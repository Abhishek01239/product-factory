# Run 2026-10-13

Decision: BUILD — Python 3.15 Readiness Check (apps/py315-check, v1.0.0)

## Problem
Python 3.15.0 (Oct 9, 2026) needs new `cp315`/`abi3` wheels. Releases pinned before October never get them, so pip compiles numpy (<2.5.2), pandas (<3.0.6), psycopg2-binary (<2.9.13), pydantic-core and PyYAML (no 3.15 wheels at all yet) from source; slim/Alpine images have no compiler. Some pins (torch 2.12.1, ctranslate2 4.8.0, onnxruntime 1.26.0, psycopg-binary 3.3.4) have no installable file. Docker `python:3`/`latest`/`slim`/`alpine` and setup-python `'3.x'` already resolve to 3.15, so teams land on it without choosing. 3.15 also removed sre_*, CGIHTTPRequestHandler, glob0/1, co_lnotab, load_module, and made strptime `%d` without a year and positional `sqlite3.connect` args errors.

## Learnings
- Check wheel availability for the pinned version, not "latest": the latest releases of the top packages mostly have cp315 wheels already; the breakage is entirely in older pins.
- A package with no wheel for a platform for any Python and no sdist is platform-specific, not broken; without that rule the report was 2x noisier on ML repos.
- Exact parent pins (pydantic -> pydantic-core) make naive "upgrade X" advice wrong; requires_dist from the per-version JSON is enough to detect them.
- 6 dev-tool checkers live, 0 posts published: distribution, not building, is the constraint.
